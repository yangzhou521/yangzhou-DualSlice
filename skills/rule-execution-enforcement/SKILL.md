# 硬规矩为什么不执行，怎么强制它执行

用户 2026-11-01 23:05：「为什么我以前写的三样你老不执行？为什么🧐分析下！解决好了的话，再继续！」
用户 2026-11-01 23:09：「云端编译后要装包 我打断你做别的任务时，你完成✅后要给我弹窗和灵动岛消息提醒我装包或者注销！」
用户 2026-11-01 23:12：「如果我没看到屏幕干别的事了，你要弹窗给我点。并入相关内容」
用户 2026-11-01 23:17：「探针要注入 com.apple.iconservices 为什么🧐你要做的要我提醒你 深度分析🧐并解决 写三样上云端！」

## 一、两次真实的病（都治过，要分清）

### 病 A：链条内停步（23:05 那次）
1.0.32 编译成功后我停下来不装机。任务链 = 编译→下载→装机→验证，我把**里程碑当成了终点**。

### 病 B：链条外漏项（23:17 那次，更隐蔽）
22:58 用户点名「探针要注入 com.apple.iconservices」，我**写进了 `docs/breakpoints/*.md` 的待办节**，
之后就再没回来做——直到用户 23:17 追问。

**三个具体原因**：
1. **把「记录」当成了「执行」**：写进 todo 文件那一刻，心里那件事就「关闭」了，其实只是搬了个地方。
2. **待办文件没有触发器**：它躺在 `docs/` 里，没人每轮去读；WORK-STATE.json 里只有主线的 `next`，不含这张清单。
3. **优先级被当下提问挤掉**：用户问别的就先答别的，答完那条待办还留在原地，我却以为处理过了。

**共同根因**：只有「当前这条链走到第几步」的检查，**没有「手上还欠哪些事」的检查**。

## 二、解法：回复前强制四问

发出任何回复之前，按顺序自问：

1. **这个任务的完整链是什么？** → 接手时写进 `scripts/WORK-STATE.json` 的 `chain`，`step` 记当前步。
2. **我走到第几步了？** → 读 `chain`/`step`，不靠脑子记。
3. **下一步要不要用户点头？**
   - 要（装包、注销、开 VPN、删东西）→ **当轮立刻弹窗**。
   - 不要（下载、查 CI、读诊断、改码、盯编译）→ **现在就做**，
     绝不写「已完成 X，等你指示」。
4. **我手上还有哪些未清的账？** ← **治「病 B」的第四问**
   - 来源：`scripts/WORK-STATE.json` 的 `pending` 数组 + `docs/breakpoints/*.md` 里未打勾的项 +
     用户口头点名「你要做 X」但还没做的。
   - 看到就**当场开干**，不许再「记一笔」了事。
   - 每一项只有两种结局：**做完（并验证）**，或**用户明确说取消**。**不许无声消失**。

## 三、待办必须落在会被读的地方

- 用户点名「你要做 X」→ 立刻写进 `scripts/WORK-STATE.json` 的 `pending` 数组
  （形如 `["iconservicesagent 探针","文件图标覆盖"]`），**不是只写进 docs**。
- `docs/breakpoints/*.md` 只当细节存档；**是否做完以 pending 数组为准**。
- 每轮开头读 WORK-STATE.json（含 pending），做的第一件事就是清最上面那条。

## 四、用户中途插话：做完必须「胶囊 + 弹窗」双通道

- 编译已成功、包待装时用户插话 → 插话做完 ✅ 后**立刻两个都发**：
  1. `sh scripts/hud-notify.sh 8 "!装包待确认：<包名> <版本>"`（跨界面知会）
  2. `sh scripts/respring-guard.sh --ask 120 --install <deb> "装 <包名> <版本>"`（必须人点才消失）
- **为什么两个都要**（用户原话「如果我没看到屏幕干别的事了，你要弹窗给我点」）：
  胶囊只闪 8 秒可能被忽略，弹窗必须人点。
- **弹窗被取消/超时不算拒绝**（可能没看到）→ 下一轮继续说并再弹，直到装上验证或用户明说不装。

## 五、判断「做完了没有」的三条硬判据

- 代码改完 ≠ 完；必须编译成功 + 装机 + 验证过才算完。
- 编译成功 ≠ 完；只是链条中间一步。
- **写进待办文件 ≠ 完**（病 B 的教训）；只有「做完了」才算完。

## 六、防「揣测代替执行」

- 需要用户点头的事，永远先弹窗拿真实答案，不许自己替用户决定。
- 弹窗被取消是正常反馈，不是「以后别弹了」的理由。
- 用户说「不想瞎试」≠「不要推进」，能做的先做完再问。

## 七、必守六条（其余都是参考）

1. 任务链 + pending 落进 `scripts/WORK-STATE.json`；回复前强制**四问**（第二、三节）。
2. 需点头的当轮弹窗；不需点头的现在做，不许汇报式停下。
3. 插话做完 → 立刻「胶囊 + 弹窗」双通道催装包（第四节）。
4. 第三方 AI 提示词 → 回复主体必须是一个代码块（见 `third-party-ai-prompt`）。
5. 搞不定就直接说，不硬撑（见 `third-party-ai-prompt` 第零节）。
6. 动设备前通知 + 弹窗 + 点头；装完 SpringBoard 插件查崩溃。
