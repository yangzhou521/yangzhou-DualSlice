# 硬规矩为什么不执行，怎么强制它执行

用户 2026-11-01 23:05 原话：「为什么我以前写的三样你老不执行？为什么🧐分析下！解决好了的话，再继续！」

## 一、根因（2026-11-01 实例：1.0.32 编译成功后我停下来不装机）

**根因一句话：规矩是「知识」，不是「动作」。读到了，但没有一个时刻强制去执行它。**

三条具体机制：

1. **没有任务链状态**。任务 = 「编译→下载→装机→验证」，每一步都靠临场判断。
   编译成功那一刻，把「里程碑」当成了「终点」——链子还剩三步，却当成做完去汇报了。
2. **规矩太多太散，实际只想起最近碰到的**。AGENTS.md 40+ 条、技能 20+、记忆 20 条。
   全读一遍不现实，于是实际遵守的只是「刚才想到的那几条」。
3. **用揣测代替执行**。装机要弹窗，预判「用户可能不想装」就不走那一步——
   拿猜测顶替行动，比做错更糟，因为连信息都没有。

## 二、解法：每次回复前强制三问（不靠记忆，靠动作）

发出任何回复之前，按顺序自问：

1. **这个任务的完整链是什么？** → 第一次接手任务时就写进 `scripts/WORK-STATE.json`
   的 `chain` 字段（如 `["改码","编译","下载","装机","注销","验证"]`）和 `step` 当前步。
2. **我走到第几步了？** → 读 `chain` / `step`，不靠脑子记。
3. **下一步要不要用户点头？**
   - **要**（装包、注销、开 VPN、删东西）→ **当轮立刻弹窗**，不许只写文字等回话。
   - **不要**（下载、查 CI、读诊断、改码、盯编译）→ **现在就做**，
     **绝对不许以「已完成 X，等你指示」结束回合**。

## 三、判断「这条链走完了没有」的三条硬判据

- 代码改完 ≠ 完；**必须编译成功 + 装机 + 验证过**才算完。
- 编译成功 ≠ 完；**它只是链条中间的一步**。
- 汇报 ≠ 完；**汇报是链条走完（或真卡住需要人）之后才做的事**。

## 四、防「揣测代替执行」

- 需要用户点头的事，**永远先弹窗拿到真实答案**，不许自己替用户决定。
- 弹窗被取消是正常反馈，不是「以后别弹了」的理由。
- 用户说过「不想瞎试」≠「不要推进」，仍然要把能做的做完再问。

## 五、规矩怎么管才有效

- **少而硬**：真正每次都执行的，压到三五条（见下），其余当参考资料。
  写得太多等于一条都不执行。
- **每条必须能变成动作**：能写成「什么时候必须做什么」的才留，写成「要重视 X」的删掉。
- **有可检查的判据**：像「回复里有没有能直接复制的块」「链子走到第几步」这种，
  自己一眼能判对错的才有效。

## 六、必守的五条（其余都是参考）

1. 任务链落盘 + 每次回复前强制三问（本技能第二、三节）。
2. 需要用户点头的 → 当轮弹窗；不需要的 → 现在做，不许汇报式停下。
3. 给第三方 AI 的提示词 → 回复主体必须是一个代码块（见 `third-party-ai-prompt`）。
4. 搞不定就直接说，不硬撑（见 `third-party-ai-prompt` 第零节）。
5. 动设备（装包/注销/杀进程）前通知 + 弹窗 + 用户点头；装完 SpringBoard 插件查崩溃。
