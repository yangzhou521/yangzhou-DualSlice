# 工作暂告一段落：先报进展总结，再上云端

用户 2026-11-06 00:20 定，**所有对话、所有工程适用**。
原话：「以后工作有进展写成后，在上云端之前先汇报这次工作进展精简总结一下……
每次工作暂时结束一段任务时给我做个简单精简的工作进展！一项一项的本次工作进展以及和上一版本对比清单🧾」

## 铁律：上云端（git_push）之前，先报总结

顺序**不许倒**：① 做完一段 → ② 报精简进展 → ③ 用户看过 → ④ 才 commit + push。
以前只零星做对账，没固定成强制动作，这就是「说了没执行」的原因。现在是硬规矩。

## 总结必须逐条覆盖这五项

1. **本次做了什么** —— 任务、优化、修复了哪些 bug（带版本号）
2. **还遗留什么** —— 没做完的任务、没修复的 bug、插件还存在什么问题
3. **下一步怎么修** —— 每一条 bug 的修法方向
4. **怎么防重复无效修复** —— 这次踩了什么坑、下次怎么避免
5. **下一版本要修什么** —— 明确的待修清单

## 格式要求

- **逐条、一项一项**，不要一段话糊在一起
- **和上一版本对比**（「本次进展 vs 上一版」），让用户一眼看出变化
- 不许只写一句「做完了」；修好的要写「已修（版本，用户确认）」，待修的写清楚
- 数据来源：`scripts/WORK-STATE.json` 的 `buglog`（唯一权威）+ `pending`

## 报完才上云

报完、用户看过，才 `git_commit` + `git_push`。如果用户看完让改，改了再报再推。
**绝不跳过汇报直接 push**。

## 例子（模板）

```
【本次进展 vs 上一版 0.0.8】
✅ 已修：B12 桌面素材加载（诊断 icon=515 hit=439）、B14 文件夹、B17 阴影
🔧 本次改：0.0.14 —— 删掉自创的 0.6s 延迟与预热闸门、补 7 个类、补 generateIconImage:、惰性枚举
⏳ 待验：B22 注销黑屏、B23 角标、B16 时钟、B15 日历、B13 选择主题、B18 控制中心、B19 设置图标
📌 下一步：装 0.0.14 注销，重点看 B22 黑屏是否消失
🛡 防复发：改动前先问「ThemeCore 是不是这么做的」，不自己发明机制
```

## 与其它规矩的关系

- `workspace-bug-ledger`：对账清单（注销回来先对账）
- `themecore-architecture-first`：改码前先问 ThemeCore
- 本技能是「一段任务收尾」时的动作，前者是「开新一段任务」时的动作，两者成对
