# 让第三方 AI 逆向分析时，怎么把话写成"一段直接发过去"

用户 2026-11-01 21:45 硬指令（原话）：「凡事让你给别的 ai 逆向分析破解的！都要以最简洁直白的话生成一段话直接发给别的第三方 AI 大模型！发给 AI 的一定要使他能最有效解决问题的不要多写也不要少写！要最能解决问题的精准地抓住我们的无法解决的要点痛点！」

## 零、搞不定就直接说（2026-11-01 22:58 硬指令）

用户原话：「以后你搞不定要别的 ai 想办法逆向分析破解的话你要真实和我说、我来找别的 ai 完成实现！不要浪费我的时间！毕竟一个智能体的能力是有限的！」

**判据与做法**：
- 一旦判定「这件事需要逆向 / 需要读我没法读的符号表 / 需要我没有的工具」→ **当轮就直说**，
  并用上面的六项结构把问题写成一块给他，让他转给别的 AI。
- **不要硬撑**：不许自己反复试、不许猜类名方法名、不许把「我再研究研究」当回答。
- 说清三件事：① 我卡在哪一步 ② 为什么我搞不定（缺工具/读不到/能力边界） ③ 已经把问题整理成可转发的一段话。
- 硬撑的代价是浪费用户时间，比答「我搞不定」严重得多。

## 交付前自检（最容易犯的错，先看这条）

**发送回复前先问自己一句：这条回复里有没有一整个能直接复制的块？**
- 没有 → **就是没做完，重写**。不要用表格、分节、清单代替它。
- 判据：用户消息里出现 **`发给 AI` / `让 AI` / `逆向` / `破解` / `分析这个包`** 这类词 →
  **本次回复主体必须是一个 ``` 代码块**；报告性文字最多 2 行，且放在代码块**之后**。

## 铁律

1. **一次给一整块**，用代码块包起来，让用户**一次复制**就能发。绝不拆成几个片段。
2. **不多写**：不写寒暄、不写背景故事、不写已排除方向的技术原理长文。
3. **不少写**：下面六项缺一项，AI 就会回头问、或者给错方案。
4. **先说形态，再说内容**：宁可少解释一句，也不能少了那个可复制的块。

## 必含六项（顺序固定）

| 段落 | 写什么 | 为什么 |
| --- | --- | --- |
| 1. 背景与目标 | 环境（机型/iOS/越狱方式）、工程形态（**Logos 还是纯 ObjC + MSHookMessageEx**）、要达成什么 | 不写工程形态，AI 会给一堆 `%hook` 用不了 |
| 2. 已经做到什么 | **带实测数据**（诊断键、计数、日志原文） | 证明做到哪一步，AI 不会从零讲 |
| 3. 卡在哪（痛点） | **一条一条列，每条附实测数据** | 核心。没有数据的"不生效"等于没说 |
| 4. 已证伪（别建议） | 我试过并实测失败的方向 + 证据 | **最能省时间的一段**，AI 最爱重复推荐这些 |
| 5. 要它回答的问题 | 编号，一个问题一行，**问"挂载点/入口是什么"而不是"怎么办"** | 问得笼统，答得笼统 |
| 6. 工具与约束 | 有什么工具、没有什么、能不能编译、怎么验证 | 否则会给一堆 otool/lldb/python 命令 |

## 反幻觉三条（必须写进去）

- **每条结论标证据**（偏移/字符串/诊断值/反汇编），**推不出就写「未证实」**。
- **绝不猜方法名**——猜的代价是安全模式（0.9.21 真崩过）。
- 若因混淆读不出符号，请给**动态探针思路**，而不是编一个名字。

## 问法要点

- 问「**真正的入口是什么（类名+方法名+实例/类方法+签名）**」，不问「为什么不行」。
- 把「看到的现象」和「怀疑的原因」分开写，让 AI 能证伪怀疑。
- 附上**现场枚举到的真实方法表**（`class_copyMethodList` 打出来的），比任何描述都准。
- 要求输出格式：**每节 = 结论 + 挂载点/代码骨架 + 验证方法 + 确信度**。
- 代码不是 Logos：凡给代码，一律要 **ObjC + MSHookMessageEx** 形态。

## 不要做的事

- 不贴整段对话历史、不贴大段源码（只贴出问题那十几行）、不问开放式大问题。
- 不要先用表格/分节讲一遍，再说"要不要我整理成一段"——**直接给那一块**。
- 不要把「我再试试」当回答——搞不定就直接说（见第零节）。

## 本工程实例

2026-11-01 给第三方 AI 的多份提示词（Mikkyy 逆向、秒加载/时钟/日历/角标、mini 文件夹、
剩余三项、UIKit 签名等）都按上面六项写；用户原话确认这种"一整块"才发得出去。
