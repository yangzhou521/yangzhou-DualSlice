# 额度最少优先（硬性规定）

用户 2026-10-31 21:10 原话：「以后所有的对话工作都以额度消耗最少为前提这个协助技能和记忆生成硬性规定并上传云端」。
**所有对话、所有工程、永久适用。**

## 为什么这是硬前提

额度是真实约束，不是口号：

- WorkBuddy 的额度包一耗尽，整条子机器人线立刻停摆（`Credits exhausted … requires an active credit package even for 0-rate free models`）。
- 实测三个不同厂商（deepseek / minimax / glm）给出的重置时间完全相同，说明限制在**账号/网关层**，换模型线绕不过去。
- 一次 `apelin_conversation_read` 读长对话能拉回几万字，等于把额度一次烧掉一大截。

## 七条做法（照做）

### 1. 不为「顺手」主动排查
用户没要求时就不查设备状态、不读长日志、不反复确认。一次查询能答的不要查第二次。
- 要设备状态：`sh scripts/device.sh read <域> [键]`（免卡片、单次）
- 要云端状态：`icli probe scripts/net-check.js` / `scripts/ci-status.js`（一个探针答一个问题，别反复查）

### 2. 不主动派子机器人
每派一条就多一份完整上下文开销；额度一紧，子线先死。**要派先问用户**。
派了之后不要长时间轮询 —— 等它自己回，或只读它最新几条。

### 3. 不重复读长内容
- `apelin_conversation_read` 尽量带 `after_seq`（上次的 `last_seq`），不要整段重读。
- 技能 / 记忆 / AGENTS.md 读过就别再整份重读；用 `file_grep` 直接定位那一行。
- 已经在本回合上下文里的结论不要重新取一遍证据。

### 4. 一轮只做一件事
把「改码 → 编译 → 装包 → 验证」压进**一个回合**，不要拆成多轮来回确认。
没有依赖关系的工具调用**放在同一条消息里一起发**。

### 5. 回复要短
- 第一句给结论（做了什么、验了什么、没验什么）。
- 不粘贴工具输出、不复述步骤、不把 diff 贴回来。
- 只有用户要求细节、或涉及「未测试项」时才展开列表。

### 6. 不做无关沉淀
只在**真的解决了问题**、或**用户明确要求**时写技能 / 记忆。
同一类问题合并进已有条目，不新建重复条目。记忆满了先删过时项再写。

### 7. bug 只登记不修
用户 2026-10-31 21:09 指示「接下来的 bug 都记录下来都不修」。
登记到 `AGENTS.md` 的「已知 bug 登记簿」，**要修必须先问用户**。
不要在没被要求时自己排查 → 编译 → 装包 → 验证一整轮。

## 边界：正确性 > 额度

省额度**不能**省掉这几件事：

- 动设备前：正文写清原因与倒计时 + 灵动岛胶囊 + 弹窗让用户点头（见 `respring-confirm-via-island-popup`）
- 装完注入 SpringBoard 的插件：查 `apelin_crash_list process=SpringBoard` 无新报告
- 要 push：先自己直接试 push，不通才请用户开 VPN（见 `notify-before-git-push`）
- 汇报里如实区分「已验证」与「未测试」

宁可多花一点额度把话说清楚，也不要因为省额度而让用户不知情、或把没验的说成验过了。
