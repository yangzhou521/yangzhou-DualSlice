# 额度最少优先（硬性规定 · v3）

用户 2026-10-31 21:10、11-01 09:02、10:1x、10:18（粘贴《省额度方案·精简总结版》）累计要求。**所有对话、所有工程、永久适用。**

一句话版：**主控存摘要，子线做隔离；通信只传锚点和 diff；方案全编号，输出限三条；工具输出先压缩，每轮摘要压历史，异常才升级。**

## 一、核心原则（五不）

不重复传背景（只传增量）· 不反复叙述（只回编号）· 不无限生成（只给限额）· 简单活轻模型 / 复杂活强模型 · 一次只问一件事但一次问全。

## 二、七条基本做法

1. **不为「顺手」主动排查** —— 用户没要求就不查状态、不读长日志；一次查询能答的别查第二次。
2. **不主动派子机器人** —— 每派一条 = 一份完整上下文；要派先问用户。
3. **不重复读长内容** —— `apelin_conversation_read` 一律带 `after_seq`；技能/记忆/AGENTS.md 用 `file_grep` 定位；工具输出不贴回对话。
4. **一轮只做一件事** —— 改码→编译→装包→验证压进一个回合；无依赖调用同批发。
5. **回复要短** —— 第一句给结论。
6. **不做无关沉淀** —— 只在真解决问题或用户要求时写；同类合并。
7. **bug 只登记不修** —— 除非用户点名。

## 三、主控—子线协议（单线 / 双线 / 多线）

### 1. 总表在调度台，子线只回变更
- **本机不是重建共享黑板**（黑板/看护/唤醒队列已废，禁止重建）：总表由调度台维护在自己对话里或 AGENTS.md，不设共享文件、不设看护进程。
- 总表列：`线号｜目标｜状态｜阻塞｜下一步｜决策人｜截止`。
- 子线回传固定四段：`状态变更｜阻塞｜风险｜下一步`。
- 主控只回一句：「按总表更新 L2，只输出 diff 和风险」——**不复述、不总结对方的整段。**

### 2. 单线给全背景，双线只传接口
- 单线：一次给完整背景，一次产出「计划 + 清单」。
- 双线：只传 `接口契约｜依赖项｜验收标准｜异常升级规则`。
- 评审固定四问：接口是否一致｜依赖是否缺失｜风险是否升级｜下一步负责人。

### 3. 最小上下文包（每次只给 6 项）
`目标 · 约束 · 当前状态 · 已有结论编号 · 本次要你做什么 · 输出格式与字数上限`。

### 4. 全部编号，用户只回编号
方案 A/B/C，任务 T1/T2，结论 L1/L2。用户回「选 B，按 T2 更新，只回 diff」就能推进 —— 不要用开放问题逼出一整轮往返。

### 5. 输出限额
只输出：**结论、变更、风险、下一步**，各不超过 3 条；不复述背景、不展开过程；不知道就写「需确认」。

### 6. 每轮 5 行摘要压历史
`已完成 / 未完成 / 阻塞 / 决策 / 下一步` —— 长对话跨轮时先给这 5 行，再做事；长文档先检索片段（`file_grep`、`offset/limit`），不全量粘贴。

### 7. 异常才升级
- 缺信息不影响推进：**按假设继续并标注**，不要停下来问。
- 只在这三种情况升级用户：影响接口 / 影响预算额度 / 影响截止。
- **同一问题 2 轮未决 → 转「决策清单」（编号 A/B/C + 各自代价），停止反复分析。**

### 8. 工具输出压缩
- 只保留决策相关字段，日志/JSON/搜索结果不整段搬进对话。
- 需要看结构化数据时用紧凑 JSON（无 indent），比缩进格式省约 30% 相关 token。

### 9. 批量提问
同类判断（多个包的状态、多条线的验收）**攒成一批一次问/一次查**，不逐条开新轮。

## 四、平台层的可控 / 不可控（如实标注）

**本机 agent 可控（照做）**：
- 稳定前缀：跨轮不变的内容（AGENTS.md 段落、任务边界、约定格式）固定顺序、不带时间戳，便于上游缓存命中。
- 长线自设预算：一条线只干一件事，做完即收；不把「顺手」塞进同一轮。
- 事实先查：状态类一律自己查完再汇报，减少「问—答—再问」。

**本机 agent 不可控（不要假装做到）**：Prompt Caching 开关、Batch API、Task Budgets、CAG/CADF 都由 Apelin 或模型侧决定；模型分级只在用户明确同意下改 `session.json` 的 `model`，不自己切。

## 五、边界：正确性 > 额度

省额度**不能**省掉：动设备前通知 + 5 秒倒计时 + 弹窗点头；装完 SpringBoard 插件查崩溃；push 先自己试、不通才请开 VPN；需用户拍板时主动弹窗；如实区分「已验证 / 未测试」。

## 七、KV 缓存资产化（2026-11-01 10:20）

- 硬规矩 / 接口契约 / 决策日志 / SOP 这类**跨线共享且稳定**的内容，**只写一处、固定位置**：AGENTS.md 的固定章节 + 技能包；跨轮只引用「路径 + 段号」，**不整份粘贴**。
- 这些段落**字节稳定**：段首不写时间戳、不写会话 ID，不随手重排顺序；改动只**追加**，不改格式。易变内容（今天进度、当前版本号）放到末尾。
- 平台侧的 Prompt Caching / Batch API 由 Apelin 与模型侧决定，agent 不可控；本机做得到的只有「稳定内容前置 + 字节稳定 + 不复述」。

## 八、压缩的反向陷阱（2026-11-01 10:20）

- 优化目标是 **tokens-per-task**（从任务开始到交付的总消耗），**不是单条消息有多短**。压过头会让另一条线反复重读、重新探索、重新推导，表面省、总账更贵。
- **压缩绝不允许丢**：文件路径（含行号）· 原始错误消息（原文照抄，不摘要）· 决策理由（为什么这样做、否掉了哪些选项、代价）· 验收命令。
- **过度压缩信号**（见到就立刻补回上下文、停止压缩）：反复重读同一文件 / 反复问已经答过的问题 / 子线要求重传背景 / 自己两次以上重建同一份认知。
- 输出的「≤3 条限额」只约束**汇报**，不约束**证据与理由**：证据、错误原文、路径、验收结果不占那 3 条额度。
- 每轮自检里加一问：**这一轮有没有为了写得短，让另一条线返工？** 有 → 压缩过度。

## 九、推理强度 / 压缩阈值 / 近 5 次工具调用（2026-11-01 10:25 用户第三条）

- **先降推理强度**：简单任务（改写、翻译、分类、格式整理、查状态）走低推理、不铺过程旁白；只有改代码/查病灶才用满推理。Harness 默认 `reasoningEffort=high`、压缩阈值 0.8（≈ 67.8 万 token 才第一次压缩），在此之前每轮都把完整历史 + 思维链重发；阈值提前到 0.3（≈30 万）就压，立竿见影。**这两项是 Apelin/模型侧的设置，agent 改不了**，本机只做减法：不把历史喂大。
- **上下文只留「最近 5 次工具调用 + 摘要」**（同基准实测：全量 71% 完成率 / 148 万 token → 近 5 次 79% / 53.5 万 → 再加摘要 91.6% / 55.3 万）。结论：砍历史不伤效果，往往更好。落地：工具输出只带回决策字段（路径、结论、错误原文），长文件用 `offset`/`limit`，读完立刻下结论，不复述。
- **缓存是「换计费」，不是「省内容」**：命中按 0.1x 计价、写入 1.25x（DeepSeek 命中 0.04 vs 未命中 2 元/百万，差 50 倍）。护住前缀稳定比写得短更值钱：同一次任务里**不要反复改技能/硬规矩段落**（击穿缓存），改动攒到任务末尾一次做。
- **工具 schema 过滤是唯一「无条件正向」的杠杆**：不用的技能不读、用不到的工具不调；本地能查的自己查（device.sh / icli probe），别让模型往返试探。
- **多 Agent 用短码不用自然语言**：每条消息固定三段短字段（`做了什么/证据/需要什么`），语义量化实测 41.9 → 7.4 token；低贡献的线**不叫醒**（本机规矩：需要它协助才叫）。通信成本按 O(n²) 涨，三条以上线只允许调度台单点汇聚。

### 九·补（2026-11-01 10:28 用户第四条，只留有增量的部分）

- **工具输出在「进入上下文之前」压**（本机最有效的一条）：命令里自己先过滤——`grep`/`awk`/`head`/`tail`/`wc -c`、只 `print` 决策字段；不要把原始长 JSON/日志先读进来再总结。需要细节时把全文写进 `.tmp/` 或 `docs/`，上下文只留**路径 + 结论**（短 ref，随时可展开）。同类做法实测：日志 7,606 → 390 token（-94.9%）、REST JSON 15,119 → 325（-97.9%）。
- **别用「花 token」的方式省 token**：压缩本身不能变成新开销——不做「先写长总结再压」，不为省 token 另派 agent、另写脚本去优化提示词。本地能确定性处理的（`grep`/`awk`/`sed`）绝不交给模型。
- **峰谷分时**：DeepSeek 高峰＝工作日 9:00–12:00、14:00–18:00，其余为空闲，空闲单价约高峰的一半，叠加缓存命中（未命中的 1/50~1/120，前提是**文本开头前缀完全一致**，中段重复不算）。落地：非紧急长活（批量整理、跨线对账汇总、沉淀写作）挪到空闲时段；用户等着的照做。政策会变，以 DeepSeek 官方公告为准。
- **按步路由而非整条轨迹绑一个模型**：一条任务里规划/病灶分析用强模型、格式化/改名/汇总用弱模型；整条绑一个会浪费 60–80% 推理预算。本机要改 `session.json` 的 `model` **必须用户明确同意**。
- **多线通信别再发明格式**：现成体系（ACCP / DRIXL / Slipstream 类）本质就是「固定短码 + 共享上下文按 ID 引用」，我们不装这些组件，照形式做——任务号/文件路径当 ID，不复述背景，单条 41.9 → 7.4 token 量级。

- **动态内容必须放尾部（零成本、最大杠杆）**：凡是每轮会变的（时间戳、当前状态、工具返回摘要、会话 ID）**只能跟在所有稳定内容之后**；插在契约/SOP 中间会把缓存命中率从 99% 打到 7%（公开实测：挪到尾部后 7% → 84~99%，成本降约 60~90%）。另注意前缀太短时可能低于模型的最低可缓存长度，命中率打折。
- **按档压缩历史与工具输出**：单片工具输出只留**首尾关键行**、约 ≤2000 字符，中间省略；长会话只带最近几条 + 已定结论，不重放全部历史（同类中间件的分档：≤6 条全量、7–20 条留近 16 条、21+ 条只留近 6 条）。要细节就留 `.tmp/` 路径按需展开。
- **重 I/O 与样板不占主上下文**：「读一堆文件只为提取一个结论」「批量改名/清点/整段扫盘」用 shell（`grep`/`awk`/`sed`）或弱模型跑完只回结论；主模型不要为了拿一个事实就把全文搬进来。
- **多线只让「有新信息」的线发言**：没有新事实就不发（回执除外），重复内容不重复汇报——冗余发言是纯开销。
- **真正的大头是少试错**：token 往往不是花在单次请求，而是「猜错→重试→重新探索」的循环。动手前把事实一次查全（诊断、`dpkg status`、`git diff`、日志尾部），别靠反复试；同一问题 2 轮未决就转决策清单，不要再试探。

## 六、自检（每轮末）

发了纯过程消息吗？整段重读了吗？输出超过 3 条了吗？问了本可自己查的事吗？有没有把该编号的东西写成开放问句？

## 附·增量（2026-11-01 10:35 起；**只追加在此处，不再改写上文**）

> 元规则：新规矩一律**追加到本节末尾**，绝不在既有段落中段插入——中段改写会改变前缀字节、把 prompt cache 打穿（外部实测：动态字段插中段，命中率 99% → 7%；只压新增、冻结前缀才让节省复利累积）。要删除或改写旧条目时留在同一提交里说明原因。

- **增量差分，不重传全量**：同一任务里第二次看同一目录 / `git status` / 同一诊断键，只报**与上次的差异**（没变就一句「与上次相同」），不再重列全部条目；状态探测类的重复执行（`ls`、`dpkg status`、`launchctl list`）同理。
- **只压新增字节**：已冻结的历史/前缀不动，压缩只作用于「这一轮新进来的工具输出与最新一轮对话」；新的沉淀内容一律追加到文件末尾固定区块。
- **可逆、fail open**：任何删减前先把全文留在 `.tmp/`（或 `docs/`）并给出路径；被丢弃的部分标 `[省略→见 <路径>]` 可随时取回。压缩若导致需要重读，即判为过度压缩，回退。
- **取回不二次压缩**：从 `.tmp/`、`docs/`、日志整段取回的内容直接使用，不再折叠一次（二次压缩是纯损失，还会打乱缓存）。
- **已知事实先查存量**：记忆、`AGENTS.md`、技能里已有的结论先查再动手，**不重复排查同一件事**；同一事实第二次引用只给「路径 + 段号」。
- **跨对话消息用固定短码信封**（借 Slipstream / DRIXL 的形式，不装库）：首行 `@to <sid前8> @t <动作> @p <路径或版本>`，动作词固定 `ANLY`（分析）/`EXTR`（取证）/`EXEC`（已执行）/`SUMM`（汇总）/`ASK`（要人拍板）/`ACK`（回执），正文三段、背景只给 ctx 路径不复述。
- **判据不变**：tokens-per-task，不是单条消息多短；重新读取变多、重试上升，就是压过头。

- **冷热分页（第七份材料，唯一新增）**：长会话把「已定稿、短期不再用的细节」（旧日志/旧诊断全文/旧构建产物清单）**页出**到 `.tmp/` 或 `docs/`，上下文只留一行可导航摘要 + 路径，需要时再**整段换入**——是「换出可换回」，不是丢弃。探索类命令（`find`/`grep`/`ls`/`cat`/`git log`）与格式化一律 shell/弱模型，不占模型（已并入⑤）。
- **fail-open 强化**：压缩只在「严格更省」时才启用；任何一步出错、超时、或压后反而变大，一律**回退原始输出**，不硬压、不赌。

- **重复行折叠成计数（第八份材料）**：长日志 / 编译输出里同一行重复 N 次的，先 `sort | uniq -c` 或 awk 折成「行 ×N」再进上下文（无损可逆，实测 tsc 输出 -70%）；短输出（≤5 行 / ≤64 token）**不压直接用**，避免小结果上的无谓开销。
- **新省法先小范围验证再固化（省 token ≠ 降账单）**：RTK 1740 次实测——宣称大幅省 token，实际账单只降 5%、有的线反涨 5%，通过率还略降。任何新省法先在一两条对话小范围试（shadow），确认 tokens-per-task 与重读频率真的降了才写进规矩；**不凭宣称数字上规矩**。
- **能单线不拆多线（CaveAgents 实证）**：多线协调成本是剪枝后单线的 2.35~3.08 倍、未优化团队可达 12.58 倍。一条线能干的活不拆多线；开新线须用户拍板（与基本②一致）。
