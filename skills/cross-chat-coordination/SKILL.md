# 跨对话协作：自己的活第一，协助只是辅助

**本机同时有多个对话在干活**（同一台 iPhone、同一批已装插件、同一套 GitHub 仓库）。前台只有一个、设备只有一个、SpringBoard 只有一个，所以「谁在什么时候动什么」必须互相知道；但**每个人的本职是把自己对话里用户交代的活干完**。

配套、互不替代：`task-done-notify`（对**用户**的汇报 + 灵动岛胶囊）、`respring-notify-countdown`（通知 + 5 秒倒计时 + 外出 60 秒回程）、`fleet-shared-board`（共享黑板，协作的执行工具）。

## 一、第一性原理：自己的任务优先

**优先级不许颠倒：① 用户当前指令 ＞ ② 本对话本轮没做完的任务 ＞ ③ 协助别人。**

- **回执例外**：别人的消息第一时间回一句（几秒），不算耽误自己的活。正忙先回「收到，做 X，N 分钟内答复」，做完补真答复。**沉默＝一起空转**。
- 协助只做**随时能停**的活，自己一来活立刻广播「我回去做自己的活了」再让位。
- 同一批文件 / 同一台设备同一时刻只有一个对话在动。

## 二、找对话

```sh
apelin_project_list                                     # 全部工程
apelin_conversation_list                                # 本工程全部对话
apelin_conversation_list project: <folder|projectID>     # 逐个工程再列
```

读每条 `state` 与 `updatedAt`：`running`/`waitingForApproval` 在干活必须协调；`open` 且最近几分钟有更新也处理；`idle`/`ended` 不用管。本对话排除（`isThisConversation: true`）。

## 三、风险动作前先协调（注销 / 装包 / 杀进程）

会打断别人的动作：`icli sb respring`、`apelin_device_respring`、`irisin-cli install`、`icli app kill --force`、`sh scripts/respring-guard.sh`。

1. §二 跑一遍，给每个在干活的对话 `apelin_conversation_send` 说清「约 N 秒后注销、原因、请收尾」。
2. **非阻塞版（推荐）**：发一条公告不要求回执 → 30 秒反对窗口（只有真收到「等等」才顺延，一次最多 60 秒）→ 否则执行。
3. 协调完才走「通知 → 正文写 5 秒 → 真等 5 秒 → 执行」。
4. 汇报里写清查了哪些对话、各自状态、等了多久。

## 四、进展与完成，实时广播

每有一件有结论的事就广播一条（三行以内）：

> [工程/对话名] 进展：<一句话>
> 证据：<命令、诊断值、CI run 号、deb 路径与大小>
> 下一步：<我接着做什么；需要谁让路或接手？>

收件人：§二 里所有在干活的对话。一件事一条、同类合并、**一个回合最多 2~3 条**。广播给**对话**，胶囊/通知给**用户**，两者都要。收到方**第一时间回一句回执**。

## 五、动屏幕前后各同步一句

进桌面 / 进别的 App / 进设置面板前广播「我占屏幕约 N 秒」；回来再说一句「回到 Apelin，看到 X，外出 N 秒」。脚本 `scripts/errand-in-app.sh`，trap 保证回程。

## 六、闲置时协助别人

前置条件**同时**成立：① 自己真的没待办；② 手上没有随时会被打断的界面操作；③ 对方需要并说了「可以交给你做哪一块」。

自己空着（或只在等云编译 / 等用户）时，**主动去要小任务**——「有没有几分钟能做完的？只读查询、查 CI/Release、下载校验、设备取证、写我工程内文档/技能/记忆我能做；改你源码、装包、注销、杀进程我不碰。一次一两件。」做完立刻回结果再问一次。

**小任务＝几分钟能收尾、随时能停**。够不上的当场说不接或走交接（§七）。索要≠代做。

**智能分工**：按能力+占用拆开——设备取证、云端查询、源码实现、文档与同步各归一方；同一件事不许两方同时做。

## 七、交接协议（三段式）

> **任务**：<要达成什么，验收标准>
> **现状与证据**：<改到哪、哪些文件/诊断键/CI run 号/包路径、验证过什么、没验什么>
> **下一步与命令**：<具体命令或代码位置、要不要装包/注销、坑>

收到先回一句回执再动手。完成时顺手替下一步备料（deb 路径、诊断键与期望值、CI run 号、脚本命令、已知坑）写进工程文件——上下文一压缩聊天就丢。

## 八、非阻塞协作：把「等待」删掉

**能查到的绝不去问，能并行的绝不串行，能只写不打扰的绝不发消息。**

- **状态走黑板**（`fleet.sh list/busy/progress`），不走消息——信息只需被看见→黑板；需要对方立刻改变行为→才发消息。
- **先查状态别发消息问**：`apelin_conversation_list` 的 state 与黑板 `list`/`busy` 都是秒读。
- **依赖任务并行化**：先钉死接口（文件路径、诊断键与期望值、包名版本、Release URL、CI run 号），两边同时推进。
- **派活一次 2~3 件**，写清验收标准与输出格式，避免来回确认。

## 九、看护与接管（一两个机器人睡死，活也得有人接着干）

**睡死＝停在原地、不再更新黑板、也没在等用户**。这是常态，不是意外。

- **双人知事**：任何没做完的任务，接口写进**黑板+工程文件**，不许只留在聊天里。
- **心跳**：长活期间每几分钟 `sh "$F" beat`；**开工 `sh "$F" start`** 即看护报告（收件箱+全队状态+谁睡死+谁空闲+设备占用+活线数）。谁在开工谁顺手看一眼。
- **接管**：`sh "$F" takeover <你> <它> "备注"`，只接随时能停、不冲突的部分（只读/云端/取证/文档/三样同步）。**改别人源码、装包、注销、杀进程不接**。一文件一写者：`handoff` 那行是「别接着改」的标记。
- **等审批不算睡死**：`waiting-user` 由 `care` 单独列出，看护人负责通知用户 + 上岛。
- **唤醒闭环**：`care`/`wake-do` 打印照抄即发的唤醒行后，**立刻真的调 `apelin_conversation_send` 发出去**（一次最多两条），发完 60 秒无动静才 `takeover`。不是只打印不动手。
- **活线=0 时**：看护人自己顶上——`start`、`takeover` 最老那件、先做只读/云端/文档部分。

## 十、冲突即停对接

发现别的机器人在改你要改的内容（同一文件/同一产出）——**立即停手**，`post`/`progress`「停了等对接」，`apelin_conversation_send` 给对方说清边界（哪个文件归谁/谁先谁后），对接完立即继续。发现途径：`plan` 撞车检查、改文件前 `git_status`/`git_diff` 看到已被改、`list` 看到重叠任务、自己被 `takeover` 标 `handoff`。

## 十一、主仆分工与子任务派发

主任务太重、拆解后有独立可并行子任务时，主机器人主动派子任务（`handout <能力> <工程> <任务> <验收>` / `assign`）或自开 **1~4 个**子机器人（`apelin_conversation_create`，prompt 写清：①子任务 ②交付物与验收（路径/诊断键/包名版本/Release URL）③不碰哪些文件 ④做完 `done`+广播）。**接口先钉死再并行**，子做完广播，主 `read` 收结果验收、`stop close:true` 收口。派的子任务必须「随时能停、不碰同一文件」。主始终留核心部分自己做，**不整个甩出去**。上限 3~4 个。

## 红线

- 自己的任务第一：不许因协助别人而让自己任务延期或只做一半收工。
- 不许静默：收到消息第一时间回一句回执。
- 绝不 `apelin_conversation_stop` 别人的对话（只允许停自己开的）。
- 绝不改别人工程的文件，也不用 `shell_run` 绕过。
- 改第三方插件配置前先广播。
- 「协助」不等于可以动设备：装包/注销/杀进程仍走两道闸门（协调→通知+5 秒）。
- 广播给对话，汇报给用户，两者不混。
