# 配置与设置面板

## 组件选择

`--preferences` 添加 PreferenceLoader 入口、PreferenceBundle 和插件专属控制器。
不需要设置面板时不生成这些内容，也不依赖 `preferenceloader`。
面板默认只有“启用插件”和固定“关于我们”；`--slider` 再添加一个演示数值行。
多模式、图片选择器、文本输入等按需求增加，不作为所有插件的基础负担。

## 单一读写规则

完整实现位于 `assets/base/Sources/__PREFIX__Preferences.h`：

1. 面板通过自己的 `setPreferenceValue:specifier:` 写一个规范配置文件。
2. 文件不存在时只从自己的持久偏好域获取兼容初始值，不复制 `dictionaryRepresentation` 的全局/注册默认项。
3. 已存在文件无法读取或格式不正确时返回错误，不覆盖损坏文件。
4. 成功原子写入后镜像完整快照到 `NSUserDefaults`，然后发插件专属 Darwin 通知。
5. Tweak 读取文件；文件不可读时才从同一偏好域回退。文件存在时，缺键使用业务默认值，不回读其他旧路径。

写入失败必须向用户显示错误，不把内存里变化的开关当作保存成功。
这是单写入方方案，不支持多个 App、daemon 与面板并发合并写配置；有这种需求时先改成明确的 IPC/串行存储协议。
原子替换防止半文件，但不等于多写入方事务。

## 默认值与快照

- 带面板工程：`enabled` 默认关闭。
- 无面板工程：`enabled` 默认开启；如果业务需要开关，再实现相应入口。
- Tweak 从不持久化默认值，尤其不能在所有注入进程的 `%ctor` 中写默认配置。
- 新增配置键，在面板 specifier 中声明默认值，并在消费端给出一致的类型和缺键回退。
- 改默认值不应覆盖用户已保存的值。确需数据迁移时增加显式版本迁移，不靠每次启动重新写入。

`__PREFIX__Config` 持有不可变字典快照。首次初始化读一次配置，通知到达后在串行队列重新读取；
高频 hook 只访问快照。之后通过主线程的同名本地通知触发 UI 更新。
已有视图需要主动观察该通知或提供刷新方法，光刷新字典不会自动重建界面。
应用恢复前台等额外刷新时机应按实际业务补充，不能假定休眠期间收到每一条通知。

## 控件

开关和文本等标准 cell 可复用，但必须验证其读写确实经过控制器的 override。
“标准开关必然不能使用”不是通用规则；关键是所有控件共享相同存储入口。
数值行使用自己的滑条组件，见 [滑条组件](custom-slider-cell.md)。

Preferences 框架要求的 `readPreferenceValue:`、`setPreferenceValue:specifier:` 保持原名。
其他新增 helper 使用插件专属 selector。面板只编译面板 `.m` 文件，不把 Tweak 的 Config 类再编译一份，
避免设置进程同时加载 dylib 与 bundle 时出现同名 Objective-C 类。

## 关于我们

控制器模板生成 Sileo、TG、QQ 三个按钮，链接来自 `assets/defaults.json`。
Sileo 和 TG 使用 scheme 优先、网页兜底；QQ 仅使用配置的深链接，打开失败提示安装对应应用。
不要自行恢复旧群号或旧二维码网页链接。

## 旧项目迁移

旧版本曾同时写多个候选配置文件，新模板不再把扫描结果当作写入位置。
原版本用户的配置若只存在于旧路径，必须先确认哪个是权威副本，再做一次性、有版本号的迁移。
不要以“整理目录”为由直接替换已发布插件的存储层；新模板的路径与同步行为仍需三环境真机验收。
