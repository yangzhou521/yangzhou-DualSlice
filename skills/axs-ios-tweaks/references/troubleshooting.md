# 排错与验证记录

## 常见问题

| 症状 | 先检查 |
|---|---|
| 两个插件有相同类名或 selector | 是否只保留 `Axs` 而遗漏插件英文名；检查源文件与 plist 字符串 |
| 设置不显示 | PreferenceLoader 入口是否打包；bundle、detail、控制器类名是否一致 |
| 找不到头文件 | 根工程 `-I./Headers -I./Sources`，面板 `-I../Sources`，源文件是否存在 |
| 滑条类找不到 | 面板 `.m` 是否编译，`cellClass`、头文件、实现是否同名 |
| 拖动变化但松手回弹 | writer 是否报错；面板与目标进程是否访问同一规范路径 |
| 只在另一个 App 不生效 | 两边实际配置路径、读权限、配置域、通知名是否一致 |
| 改配置后现有视图不变 | 是否观察配置刷新通知并在主线程应用 |
| 隐根读取不到 | 当前 scheme、官方路径转换 API、文件权限、prefshook 行为；禁止扫目录猜写入目标 |
| `unexpected character` | 编码、BOM 和报错字符；不要把所有语法错误都归因于 BOM |
| `missing context for method declaration` | 方法是否位于正确的 `@implementation` 内 |
| 切换环境后链接或运行异常 | 是否在每次 scheme 前 clean；是否使用正确的库与工具链 |
| QQ 按钮打开旧群 | 旧项目控制器仍是旧链接；修改默认配置不会追溯更新已生成项目 |

doctor 是辅助检查，不是 Objective-C 编译器。自定义协议 override、外部类声明等复杂写法
可能超出它的规则；确认原因后更新检查规则，不要为了通过它破坏正确的系统 API。

## 版本整理时的修正

2026-10-23 整理版做了以下结构与约定变更：

- 从 Markdown 中复制整套代码，改为 `assets/` 实体模板加生成器。
- 所有自定义标识加入插件身份，不再复用裸作者前缀。
- QQ 深链接集中配置，移除旧二维码网页链接。
- 每个打包 scheme 前分别 clean。
- Tweak 不再持久化默认值，面板单写入方；热点读取配置快照。
- 路径层使用工具链提供的 API，移除通用模板里的手动 `dlsym` ABI 假设与目录扫描。
- 三环境构建是分别编译，不能把“共享源码”解释为“共享同一个二进制”。

原目录在修改前已备份到桌面同级 ZIP，历史细节可从备份对照；不在活动文档中继续维护重复模板。

## 历史经验的来源

旧文档记录：KeyboardTools 的 `jbroot()` 跨进程交换文件方案曾经多用户实测；
Snapper4、ScreenShellPro、TweakHub 有多环境资源路径经验；DuoStatus 验证过自定义滑条。
这些是旧文档的项目记录，不是本次重构模板的测试结果，也不证明当前设备/工具链仍然兼容。

保留的经验是：跨进程必须访问同一份配置、不能用扫描结果决定写入目标、读写失败要可观察、
滑条由控制器统一保存。旧代码的多候选镜像、动态符号探测、缓存策略不能未经验证直接当作通用标准。

## 工程检查

```sh
python3 scripts/doctor.py /work/touchtrail
```

检查生成工程的必要文件、命名空间、plist 和本地头文件引用，不修改工程、不执行编译。
检查通过后仍需按构建文档编译，并在目标设备验收。

## 真机验收

Rootful、Rootless、Roothide 分开记录设备、iOS、Theos/头文件版本、包版本和日期：

1. 先检查 deb 内容，再安装到用于测试的设备，确认目标进程与过滤器一致。
2. 面板启用、关闭，确认关闭时没有插件行为，原行为正常。
3. 面板修改值，记录面板与目标进程实际解析出的规范路径及读写结果。
4. 滑条拖动、松手、列表复用、VoiceOver、旋转和大字号分别检查。
5. 确认目标进程收到通知、刷新快照并应用 UI；重启进程后配置仍在。
6. 同时安装两个不同插件，确认面板、类名、配置域、通知与资源互不串用。
7. 验证 Sileo/TG 兜底和 QQ 新群链接，确认未安装应用时的失败提示。

本次 Windows 工作区不能替代上述 Theos 编译与真机验证。
